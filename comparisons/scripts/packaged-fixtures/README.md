# Batch 03 fixture modules

Every Batch 03 package beyond Batch 02's six has one fixture module here, `<name>.mjs`, named like
the package's workflow. `idiomatic-fixtures.mjs` loads every module at import (files starting with
`_` are support, not fixtures), and the per-package checks in `../packaged-checks.mjs` run it:
`verify-packaged-ports.mjs` for every package, and `check-packaged-port.mjs <name>` for one while
you author it. The modules live outside the package roots because every file under a root is
fingerprinted.

A module imports only Node built-ins and `./_support.mjs` (`git`, `writeFiles`, `commitAll`,
`enumOf`, `leaf`), never `../idiomatic-fixtures.mjs`, which loads it with top-level await.

## The fixture repository

Each run starts from a fresh Git repository (`env.cwd`) with two commits: `target.mjs`
(`export const value = 1;\n`) and `.gitignore` at `env.since`, then `README.md` at `env.until`
(HEAD). `env.root` is a scratch directory beside it; runs use `env.stateDir` and `env.worktrees`.
The run's grants are `all`, its agent limit is 1, and every harness reply is inert: nothing happens
unless a reply makes it happen.

## Exports

| Export                                             | Required | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| -------------------------------------------------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `input(env)`                                       | yes      | The workflow input of the success run and of the fault matrix.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `reply(request, env, mode)`                        | yes      | The output of one agent call: an object for a schema call, else a string. Key on `request.call.stepId`; `request.options.prompt` is the rendered text, `request.cwd` the call's working directory (a worktree for an isolated writer), `request.outputSchema` the JSON Schema. A writer's reply may write files under `request.cwd` before it returns. Throw for an unexpected step.                                                                                                                                                                        |
| `check({ result, env, calls, record, suspended })` | yes      | Assert the success run: `result` is the completed run, `calls` the harness requests, `record` the saved run. Check the output contract and the filesystem the workflow should leave.                                                                                                                                                                                                                                                                                                                                                                        |
| `setup(env)`                                       | no       | Add files to the fixture repository before the run (use `writeFiles` and `commitAll`); it may add fields to `env`, which the kill worker receives too.                                                                                                                                                                                                                                                                                                                                                                                                      |
| `answer(question)`                                 | no       | The inbox answer of a durable question, or `undefined` for the default: `{ approved: true }` for a step whose leaf is `approve-<name>`.                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `fail(request, mode)`                              | no       | Return true to fail this call as a nonzero process exit (for modes).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `kill`                                             | no       | The F3 kill point of a port that writes: `{ step, boundary, writeLocation, pristine? }`. `step` is a regular expression source matched against step IDs; `boundary` is `'response'` (killed after the matching agent's reply wrote its files, before its response is recorded) or `'checkpoint'` (killed after the matching step completed, before its checkpoint is appended); `writeLocation` is `'isolated-checkout'` or `'source-checkout'`; `pristine: false` when the run legitimately leaves `target.mjs` changed. Omit `kill` for a read-only port. |
| `degraded(output)`                                 | no       | True when the output admits a degraded result that its `status` does not show (a failed tolerant member, an unchecked candidate); the fault matrix records it as `outputAdmitsDegradation`.                                                                                                                                                                                                                                                                                                                                                                 |
| `readOnly`                                         | no       | The F3 "not applicable" reason for a read-only port.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `modes`                                            | no       | Extra contracts: `[{ mode, input?(env), options?(opts, env), rejects?, check }]`. Each runs fresh with `harnessFor(..., { mode })` (your `reply` and `fail` see `mode`); `check` asserts the outcome, then a resume must pay nothing again. With `rejects` (a RegExp) the run must fail with it and `check` gets the failed record.                                                                                                                                                                                                                         |

F1 fails the first agent call as a process exit and F2 returns a schema-invalid reply to the first
schema call; both must resume to completion without paying for a completed call again. F4 wraps the
workflow so that its first run throws, then accepts a one-statement code fix on resume. F5 counts
the durable questions the success run suspended on.
